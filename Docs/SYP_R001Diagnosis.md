## Max 的真实驱动链

右眼：

```text
SYP_R001
  → Point164 的旋转表达式（眼球中心处的 Point helper）
  → ZPoint074 / 075 / 076
  → Sphere074 / 075 / 076
  → KPoint074 / 075 / 076（部分有额外位移、旋转表达式）
  → zCircle074 / 075 / 076
  → Link_Constraint
  → Bone027 / 028 / 029
  → Skin
```

左眼对应 `Point004`、`zCircle068/069/070` 和 `Bone036/037/038`。

骨骼的普通父节点虽然显示为 Eye_R / Eye_L，但 transform controller 是 Link_Constraint，其目标才是真正的动画驱动。只检查普通父子树会漏掉这层关系。

Point164 的世界位置（Max，cm）：`(-3.15057, -4.08607, 159.558)`，与眼球中心重合。它不是运行时碰撞体，而是改变子节点位置和朝向的变换枢轴。

Point164 的旋转表达式包含：

```text
X = -YanJing_R001*0.01 - YanJing_Zong001*0.01
Z = SYP_R001*0.28 + YanJing_R001*0.01 + YanJing_Zong001*0.01 - BiYan_R001*0.092
```

表达式旋转量为弧度；不能将这里的 `0.28` 当作角度系数。变量绑定和控制限位也应随迁移数据一起保存。

KPoint074 还有额外的三轴旋转表达式：`SYP_R001*-0.063`、`-SYP_R001*0.021`、`SYP_R001*-0.201`，以及分段位移表达式。因此内眼角不能仅靠固定世界轴的端点插值精确复现。

### 导入数据

- 从 UE SkeletalMesh 的 LOD 读取了 408 个眼睑骨骼影响顶点，逐个按参考位置匹配 Max 顶点。
- 最大参考位置距离：`0.000289 cm`（约 `0.00289 mm`）。
- 最大单项权重差：`0.000092787`，没有权重差大于 `0.001` 的匹配点。
- 两边眼睑区域均支持最多 8 个骨骼影响，没有发现退化为 4 权重的证据。
- Max 有 410 个眼睑影响顶点；导入会裁剪极小权重，阈值附近的影响集合数量不能直接当作拓扑缺失。
- Max Skin 虽然 enableDQ=true，但受这 6 根眼睑骨影响的 410 个顶点，DQ weight 全部为 0。此区域实际使用线性蒙皮。

这些检查支持“主要是驱动实现错误”的结论，但不是对所有网格、LOD、表情组合的完整导出审计。

## Unreal 的正确实现方式

1. 在 Control Rig 中为 Point164 / Point004 建立 Null（或不显示的辅助控制），让它们跟随 head 所在空间。枢轴变换来自 Max 实测，不能固定在角色世界坐标。
2. 保存眼睑驱动目标相对于这些辅助枢轴的初始变换。
3. 将 SYP 限位值映射为原表达式的输入，在相同局部空间计算辅助枢轴旋转。
4. 按原顺序求值 KPoint 的附加位移和旋转，再合成枢轴变换，得到骨骼目标的完整位置、旋转、缩放。
5. 在 Forwards Solve 中使用这些目标设置骨骼，处理好眼周点控的叠加顺序。只复制闭眼这一条表达式不足以复现眼睛方向控制的组合行为。

只有刚性绕枢轴旋转这一项时，等价的世界空间公式为：

```text
p(s) = pivot + deltaRotation(s).RotateVector(p_initial - pivot)
q(s) = deltaRotation(s) * q_initial
```

两个公式必须使用同一个坐标空间的旋转增量。含 KPoint 表达式的目标，需要先应用其局部修正，再组合父级枢轴，不能只套上式。

FBX 不会把 Max 的表达式控制器和 Link_Constraint 自动变成 Control Rig 图。保留蒙皮与参考骨架即可在 UE 重建虚拟体，无须把它当成可见网格或物理碰撞体导出；离线动画也可以选择把最终骨骼变换烘焙到 FBX。
