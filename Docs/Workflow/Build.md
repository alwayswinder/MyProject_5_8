# 按角色名称表搭建面部 Control Rig

本流程用于后续接收一张角色控制器名称表后，完成 Max 探测、UE 搭建、验证和交接。适用工具为本项目 UE 5.8.3、3ds Max MCP 和 UE Python 远程执行。用户自行检查画面，不使用 computer-use。

执行前读取 [迁移配置](../migration.config.json)；工具和脚本选择见 [Tools.md](Tools.md)。本文件是唯一的端到端执行流程，其他配方只解释具体部位。

## 1. 接收表格

入口文件：

- [全部控制器名称参考](../Reference/ControllerNames.md)：本次指定 / 成对补全的 46 项，以及已有基础 26 项。
- [新角色 Markdown 表](../Templates/CharacterFaceControllers.md)：方便直接填写、发给 Codex。
- [新角色 JSON 表](../Templates/CharacterFaceControllers.json)：便于程序读取，72 行以 `role_id` 固定功能对应关系。
- [Seven 已填写实例](../Characters/Seven.face-controls.json)：精确名称和文档索引范例，数值参数限于 Seven。

新角色至少提供：角色名、Max 场景、采样帧、UE SkeletalMesh、目标 ControlRig 路径，以及启用功能的 Max 精确名称。基础 Rig、口型参考图为可选项。用户只需填功能对应的控制器名；目标骨骼、Morph、控制层、轴向及系数由执行阶段探测补齐。

`role_id` 固定功能语义，`max_name` 填新角色场景内的真实名字，`ue_control` 是输出控制名。不同角色可使用相同的 UE 控制名，资产路径分别管理。没有的功能设 `enabled=false`，并在 `notes` 写明原因；启用但留空的名称标记为待补，继续处理可独立完成的组。

### 表结构约定

| 字段 | 说明 |
|---|---|
| `schema_version` | 当前为 1 |
| `character` | 独立角色标识，用于参数和交接目录 |
| `source.max_scene / sample_frame` | 源场景路径及采样帧，核对当前打开文件后再采样 |
| `target.skeletal_mesh / control_rig` | 明确的 UE 网格和 Rig 资产路径 |
| `target.base_control_rig` | 可选基础 Rig；为空时从目标网格建立所需层级 |
| `bindings[].role_id` | 固定功能编号，沿用模板 |
| `bindings[].max_name` | 新角色的 Max 精确名称，不支持靠前缀自动猜相似对象 |
| `bindings[].enabled` | 本次是否搭建该功能 |
| `bindings[].recipe_doc` | 按功能查实现文档；Seven 数值作为结构参考 |
| `bindings[].reference_max_name` | 仅模板中的 Seven 名称提示，不是新角色绑定 |
| `reference.reuse_numeric_parameters` | 默认 false；新角色重新采样和拟合 |
| `layout` | 用户已确认的摆放偏好，用新角色头部尺寸和坐标重新布局 |
| `optional_assets.phoneme_reference_texture` | 可选参考贴图，不影响表情求解；图形与滑块前后分层 |

默认 JSON 模板 72 行均启用；按角色实际需要关闭缺失或不需要的行。Markdown 表与 JSON 都可作为执行输入，给出其中一种即可。

## 2. 核对新角色源数据

1. 对照场景内精确名称、唯一性及左右含义，核查启用功能和 UE 网格是否存在。歧义记录到角色报告，缺少的功能先单独标记，不用其他名字替代。
2. 读取每个源控制的父级、Transform、Position / Rotation List、活动层、底层 Float Limit、Wire / Expression 绑定、Link Constraint 和辅助虚拟体。层号按角色读取，不能统一假设为第 2 层。
3. 从新网格骨架建立导出骨清单，枚举全部有效 Morpher 通道；建立源骨与 UE 骨的对应，核对参考姿势、有符号缩放、单位及坐标转换。骨骼或 Morph 名称可以与 Seven 完全不同。
4. 保存原采样帧、被修改层的底层原值及相关预览输入。限位下的 Bezier 原值也要保存。采样在关闭自动关键帧的环境进行，成功和异常路径都恢复并读回，不把统一归零当作恢复。
5. 每个有效轴覆盖中性、中间值、正负端点、越界及回零；左右各自采样，记录完整骨骼位置 / 四元数 / 缩放、Morph，以及必要的枢轴和顶点响应。虚拟体、FFD 或 Skin Wrap 等源变形需要继续查明其贡献。
6. 同时采集会共享目标的组合：眉毛整体 / 点 / 弯曲；上 / 下眼皮 / 眼球 / 总目标；中央 / 侧嘴唇 / 嘴角 / 总嘴控 / 下巴；鼻子整体 / 鼻侧；整体表情 / 眼神 / 口型。按新角色实际依赖确定组合。

控制器名只负责找到功能入口，实际输出从源驱动链和响应数据确定。沿用新角色现有的目标骨骼 / Morph；导出缺少必要数据时，将对应功能记录为缺少源资源，补齐后继续。

## 3. 生成该角色参数并搭建

先读取目标资产实际类型。`ControlRigRuntimeAsset` 通过 `get_editor_asset()` 取得图编辑接口，通过 `hierarchy` 取得层级，测试实例由编辑数据的 `create_rig_vm_host()` 创建；旧 `ControlRigBlueprint` 的直接方法不能原样套用。Seven 同角色完整图迁移入口及验证见 [新式资产记录](../Evidence/SevenRuntime/README.md)。该入口只允许空目标，不是新角色自动适配器，也不能重复执行覆盖已有控制。

将角色映射、采样、拟合、验证报告存到 `Docs/Evidence/<角色名>/`，角色说明与已填表存到 `Docs/Characters/<角色名>/`，并保留用户提供的已填名称表。记录参考误差和验证范围；新角色不能覆盖 Seven 证据。

**现有 `Scripts/build_*.py` 多数硬编码 Seven 的 Rig 路径、骨骼名和证据目录。** 迁移新角色时，先生成独立角色参数及对应构建入口（核对脚本直接 / 间接读取的参数、导入模块、临时输入文件和目标路径），将输出资产明确指向表中目标，再执行。按需抽取通用函数；Seven 的既有资产保持可追溯。

按依赖搭建，通常为：

1. 导入或核对目标网格骨骼层级、预览网格、形状库和求解入口。
2. 已启用的眉毛和眼周基础点控，上 / 下眼皮及其虚拟枢轴运动。
3. 六嘴唇、脸颊、鼻子整体、嘴角与总嘴控，将共享骨骼贡献接到同一最终姿态写入前。
4. 单眼目标、双眼总控及眼皮 / 眼袋联动，核对控制初始位置，避免目标落到 Root 原点。
5. 下巴枢轴及嘴部联动、鼻侧扭转；与已有平移或旋转按源顺序合成。
6. 整体表情、口型和眼神 Morph 控制；每个目标曲线明确来源，组合逻辑来自采样。
7. 面板布局、控制颜色和可选口型参考图。

如果仅启用部分功能，补齐其必要的内部求解依赖；不能为满足固定顺序而要求用户提供所有可选手柄。

修改前备份磁盘状态和保存当时内存状态；现有 Rig 增量修改时保留原控制、关键帧接口及预览输入。控制自身 scale 为 1，形状尺寸使用 shape transform；初始 / 当前偏移都设定。执行链保持单一可达顺序，同骨骼的贡献先合成，避免后面的 SetTransform 覆盖前面的结果。

### 按用户已确认偏好布局

| 内容 | 偏好 |
|---|---|
| 面部点控 | 按新角色对应部位摆放，大小与点间距适配 |
| 鼻侧 | 两个小手柄放鼻子整体下方，左右分开 |
| 整体表情、口型 | 玩家正面视角的画面右侧，按各组表中顺序整齐排列 |
| 眼神 | 玩家正面视角的画面左侧，靠近角色，左右两列，每列气 / 怒 / 忧 / 笑 |
| 水平滑块 | 玩家视角从左到右增加权重；Seven 行程为 8 cm，新角色按尺寸适配 |
| 口型参考图 | 同行对齐，在滑块平面后方；Seven 后移 6 cm，新角色按比例检查拾取 |
| 下巴 | Seven 采用初版 1/3 的 UI 行程并补偿增益，保留完整动作；新角色按源行程和头部尺度确定 |

“画面左 / 右”以玩家正面视角为准，和角色自己的解剖左右分别记录；Max / UE 坐标方向重新核对。Seven 的绝对 X/Y/Z 和固定 Root 空间不作为新角色通用坐标。新角色若要跟随头部动画，应采用对应头部空间并验证，不能把静止参考姿势的通过扩大为动画适配通过。

## 4. 逐组验证与持久化

统一执行 [Control Rig 验证规范](Validation.md)，数值部分优先使用有效临时实例；用户负责最终画面确认。

- 先断言骨骼、控制与曲线真实存在，完整层级已初始化；再比较源中性和多档完整变换。
- 同时报告绝对参考姿势误差与动作增量误差；记录拟合残差，不能用端点或单一欧拉角替代完整旋转验证。
- 每组单控、左右、组合、无效方向、限位、初始值、回零和重复求解均检查；已有控制和 Morph 输出做回归。
- 骨骼与曲线确实驱动预览网格。新增 Morph 后还需正常动画帧中的实际动画曲线检查；遇到缓存时保留输入、重开编辑器并复查，不仅查看 Rig 层级曲线。
- 保存、关闭资产编辑器、重新加载包，复验结构及数值，恢复原预览输入。临时预览采样结束后检查最终动画曲线也已恢复。
- 更新角色说明、已填名称表、映射和验证证据；标明已完成、缺少资源、已知近似及待用户画面检查的功能。

Seven 的上眼皮约 0.393° 组合残差、脸颊既有参考偏差、早期眉毛 / 眼周的历史验证范围均保留在原文档中。新角色逐项形成自己的结论。

## 5. 交接与执行示例

用户后续可以发送：

> 按这张角色名称表，参考 `Docs/Workflow/Build.md`，完成已启用的面部 Control Rig 控制。Max 和 UE 已打开，画面由我确认，不使用 computer-use。

执行阶段按该请求自动推进源探测、角色参数生成、目标构建、数值与重载验证，并补齐角色文档。完成回复说明目标 Rig、已启用功能、手柄位置 / 操作和实际验证范围。JSON 名称表是此流程的输入；已有 Seven 专用脚本需完成角色适配后运行。

## 6. 每个角色的完成条件

| 产物 | 应包含 |
|---|---|
| 已填名称表 | 启用功能、Max 精确名、UE 控制名、目标资产；缺失或停用项有原因 |
| 源采样与映射参数 | 活动层、原始范围、目标骨 / Morph、空间转换、枢轴、拟合残差及输入恢复结果 |
| 角色构建入口 | 可追溯的目标路径和依赖；首次添加、增量修改、重建边界明确 |
| 验证证据 | 源对照、原控制及曲线回归、组合、初始 / 回零 / 限位、预览曲线、保存重载 |
| 角色记录 | 当前目标和计数、操作方式、已知近似、待用户确认项；历史批次计数不写成当前状态 |

用户只需提供输入表和资源信息，并确认最终画面。AI 负责按上述产物完成交接，不要求用户逐个研究内部脚本。
