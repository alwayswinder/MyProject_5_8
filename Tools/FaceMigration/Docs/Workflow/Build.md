# 以示例 Rig 和 Max 源场景适配面部 Control Rig

本文件是唯一端到端流程。默认以用户指定的成熟 UE Rig 为示例，继承控制设计和可用求解，结合 3ds Max 核对、补齐和适配。无需从零重建，也无需为证明迁移独立而替换已有实现。接口按实际 UE 版本和资产类型选择，最终画面由用户检查，不使用 computer-use。

先读[迁移配置](../migration.config.json)、[工具选择](Tools.md)和[验证规范](Validation.md)。2026-11-10 用户已明确允许参考已有实现；此前“不参考已有实现”的要求只属于上一轮流程测试，不再是默认要求。

## 2. 备份并读取示例契约

修改前备份目标磁盘包、当时内存状态和预览输入。记录示例包摘要，不保存或改写示例。枚举形状库、材质、贴图、函数和骨架依赖；缺少依赖不能悄悄换成统一默认形状。

将当前信息记入本任务 `Current/Evidence/reference_inventory.json`：

| 类别 | 必须读取并保留或明确适配的内容 |
|---|---|
| 动画接口 | 控制名、显示名、类型、默认值、通道、父级和空间，已有 Sequencer 兼容性 |
| 手柄外观 | `shape_libraries`、形状名、初始/当前 shape transform、颜色、可见性和分组 |
| 手柄操作 | 初始/当前 offset、允许轴、限位启用状态、上下界、UI 行程、输入增益及重置位置 |
| 面板辅助 | 滑轨、端点、绘制指令、Visual Cue、口型参考图、材质及前后层次；不混入动画控制计数 |
| 求解 | 图和函数、执行顺序、骨骼/曲线输出、共享目标贡献顺序、枢轴和辅助链 |
| 运行依赖 | 预览网格、骨架版本、源资源路径和坐标空间 |

参考和目标用同一姿势、相近正面视角、缩放、选择状态及调试显示作对照。截图说明外观目标，准确参数以实际示例资产读取为准。方法和本次两张图见[形状与摆放](MigrationGuide.md#23-控制形状与摆放)。

盘点必须实际读到依赖，不能只复制属性。2026-11-10 实测：目标初始只有一个 `/ControlRig/Controls/DefaultGizmoLibraryNormalized`，示例另有项目内 `/Game/_MyTest/Mouth/LidDiagnostic/PhonemeReference/SL_PhonemeReference`（依赖 `SM_PhonemeReference`、`M_PhonemeReference`）。构建只复制 `shape_libraries` 属性，不会检查这些包能否加载；换项目缺包时 73 个手柄会退回默认形状而数值仍全部通过。因此构建后要再断言一次：每个控制的 `shape_name` 能在形状库解析，库引用的网格和材质资产存在。UE 5.8.4 的可用读取方式见[工具选择](Tools.md#参考契约盘点ue-58-形状-api)；`gizmo_name`、`gizmo_color` 已废弃。

## 3. 选择改动最小的适配路线

| 情况 | 默认路线 | 边界 |
|---|---|---|
| 同角色、同网格、同资产类型 | 从示例复制为独立目标，或增量恢复已有目标中缺失的部分 | 保留成熟接口、形状和求解，只改本次差异 |
| 同角色、Blueprint 转 RuntimeAsset | 迁移完整层级、图、控制设置及显示依赖，再验证 API 和实例 | 不是只复制节点或只复制 72 个动画控制 |
| 目标已有内容 | 比较目标与示例，按差异增量修复 | 空目标构建器不能直接执行，不能为满足断言先清空目标 |
| 新角色、不同骨架或 Morph | 继承控制语义、形状体系、面板组织和可用图结构，重新绑定和定参 | 不整套照搬 Seven 的绝对坐标、骨骼名、参考变换和增益 |
| 示例缺项或确认有错误 | 对缺项采样并局部实现或修复 | 先查 Max 驱动，仅重建无法复用的部分 |

完整迁移入口和重跑边界见[工具选择](Tools.md#示例派生与新式资产迁移入口)。路径映射必须保持示例和目标不同。`Jobs/seven-runtime.json` 是旧配方适配配置，其合并资产映射不能用于同时读取示例和目标的整图迁移。

### 新角色与示例骨架相同的情况

“新角色”不等于必须重新拟合。先独立探测，再判定：

1. 重新读取目标骨架、网格、单位、参考姿势、Morph 集和轴向，不读示例缓存。逐骨比较名称与顺序，逐 Morph 比较名称。
2. 若骨名与顺序、参考姿势、Morph 集、单位和轴全部一致，且目标没有既有求解，则记为“等价核对通过”：允许继承示例的控制数值、形状和求解，只需重新核验 Max 动作。
3. 若有不一致（骨名、数量、单位、有符号缩放、参考姿势），按[主流程](#1-确认示例源数据和目标)逐项重新绑定：新骨映射、Morph 映射、控制父级与枢轴、输入增益和行程，并重新采集覆盖新行程的 Max 样本。
4. 两种结论都要写进 `adaptation_report.json` 的 `binding_probe`，说明判定依据；不能因为“看起来是同一角色”跳过第 1 步，也不能因为“声称新角色”就重复拟合已证明一致的部位。

2026-11-10 实测：`NewControlRigRuntimeAsset1` 与示例同为 149 骨（名称与顺序一致）、同一 `Seven` 网格、87 个 Morph 全含，判定为等价核对；因此这一轮继承示例参数，只对 1175 组迁移等价和上眼皮 Max 抽检负责，其余 71 个控制没有重新拟合，须在报告中写明。

不默认采用全量辅助链拟合、大量多项式节点生成、统一球形手柄或统一归一化行程。示例有可用实现时优先保留并核验；拟合用于已定位的差异和新角色适配。

### 已有求解正确、控制设计不同的情况

先核对目标现有求解的来源及验证范围，再分开处理显示与输入。可以保留目标的完整执行链、辅助层级、骨骼/曲线输出和头部跟随，移植示例控制设置与显示资源，并在原输入端增加转换层。不能仅复制 offset、形状或限位：示例的上眼皮用 Z 轴 10 单位，采样版曾用局部 Y 轴 1 单位；表情增重方向、下巴倍率和眼球世界位移也各有约定。

转换关系显式记为 `Max_raw = M × UE_UI`，然后按原求解器的采样尺度归一化。控制父级改变时，先保留初始世界 offset，再转换到新父级；Initial 值重新按示例写入，避免保世界操作留下错误补偿。预览输入先换成源语义，再换到新接口，不能直接回填旧数值。资产脚本查询层级键时按元素类型和名称比较，不能依赖 Python 包装对象的相等性。

原拟合区间不是源限位。恢复更长行程时，区分源 Float Limit、示例 UI 限位和图内人为 Clamp；重新采集覆盖恢复行程的 Max 样本，验证通过后才保留该行程。外推不通过时修复对应模型，不能用裁短示例行程掩盖问题。眼球原本无源限位时，不沿用上一轮宽视线测试区间作为永久硬限位。

滑轨是独立的执行绘制节点，不随形状库或层级复制自动出现。复制其默认点、颜色及粗细，接到原执行链尾部，保留全部原执行连接。挂到头部的控制还需验证头部动画；需要随头运动的绘制点也应明确空间。RuntimeAsset 的预览网格从 `preview_skeletal_mesh` 读取，不调用 Blueprint 专有方法。

头部跟随时，面板绘制的 `WorldOffset` 使用 `inverse(Head_initial) * Head_current`（UE 变换乘法顺序），让静态参考点随头部整体移动。显示与输入仍分别管理，不能用修改控制自身 scale 来补偿。结构体颜色按 RGBA 分量比较，不按包含包装对象地址的字符串比较。

## 4. 结合 Max 核对动作和差异

1. 核对名称唯一性、左右含义、场景和时间；读取活动 Position/Rotation List 层、底层 Float Limit、Wire/Expression、Link Constraint 和必要辅助体。对带 Position XYZ / 列表控制器的点控，`in coordsys world move` 不会驱动骨骼，必须直接写 `node.position.controller[2].value`；判断“控制无效”前先确认设值确实改变了源值（详见[探测方法](MigrationGuide.md#13-探测脚本要点)）。
2. 保存帧、底层原值及预览输入，关闭自动关键帧采样。场景不一定处于中性：2026-11-10 当前 Max 的 `Seven_Head` Morpher 通道 53/54（`L`/`R`）为 100.028，55/56/57 有 9e-5 噪声；采样前要记录全部 Morpher 通道值与控制器原值，成功和异常都逐项恢复并读回，不能把归零当作恢复。
3. 同角色先用当前 Max 样本核验示例的单控、正负方向、中间值、端点、回零和共享目标组合。可靠参数可以保留，历史报告只作为线索。
4. 新角色重新建立源骨、UE 骨和 Morph 映射，核查参考姿势、有符号缩放、单位、空间及枢轴；继承控制设计不等于继承旧角色数值。
5. 比较完整位置、四元数和缩放，同时记录 Morph。虚拟体、FFD、Skin Wrap 等效果须查明，不能凭骨骼数相同推断变形均已覆盖。
6. 每组标为“示例直接保留”“已适配”“已修复”“缺少资源”或“待验证”，记录依据。

比较源与网格的中性姿势时，单列原始参考差异。如果使用每骨固定参考配准，保留配准规则、原始差异及当前原始样本摘要，分别验证完整配准姿势和源动作；不能把配准后的误差描述成 Max 原始参考姿势与 UE 完全相同。

源没有限位时，先继承示例合理的 UI 行程并补采其覆盖范围；新角色按实际操作和头部尺度定行程。不能为了得到较小拟合误差，默认把所有无限位点控裁到 ±1 源单位。未覆盖的行程须说明，必要时扩充采样。

正负分支必须加入“门控轴为零、另一轴有值”和阈值两侧的样本。2026-11-10 恢复行程时发现，右脸颊横向为零、仅竖向输入的眼袋分支曾偏差约 2 mm；随机组合避开零点，不能发现这一问题。应读取实际源阈值并修复比较节点，不能统一假定所有分支均以 `>= 0` 为边界。

## 5. 按示例完成目标

先选眉毛或眼皮一组、一个水平滑块及视线总控，检查复用路线、比例、操作轴和重置，再应用到其余组。用户已给出明确示例时按示例推进，不要求每组再次批准；已有明确负面反馈必须修正。

按源依赖处理眉眼、嘴唇、脸颊、鼻子、嘴控、视线、下巴和 Morph。共享骨骼先合成贡献，保留旋转和枢轴顺序；执行链保持可达，避免后写覆盖。继承完整图时不必为遵守搭建顺序拆掉重建。

### 外观和操作是必交内容

| 项目 | 默认要求 |
|---|---|
| 面部手柄 | 保留示例各部位形状、配色和尺寸比例；贴合目标解剖，避免眼口区域遮挡 |
| 控制缩放 | 控制自身 scale 为 1，显示大小走 shape transform；初始和当前状态一致 |
| 面板 | 保留滑轨、端点、行序、间距、分组色和可读性，不用限位线替代轨道 |
| 布局 | 玩家正面视角：眼神在左侧、分眼两列；整体表情和口型在右侧；保持示例与脸部的相对距离 |
| 滑块 | 从画面左到右增加权重；同一 Seven 保留示例 8 cm 行程及增益，新角色按比例适配 |
| 口型图 | 示例已有图时保留逐行对齐、材质、透明边界及前后层次，不因它不参与求解而省略 |
| 鼻侧和视线 | 鼻侧在鼻子整体下方；总控/单眼目标重置后仍在眼前，不能回到 Root 原点 |
| 下巴 | 保留示例已调整的短行程和补偿增益，不能在已缩短的基础上再次除以三 |
| 限位显示 | 继承示例设置，分别处理输入约束和调试可视化；正常操作不应出现覆盖头部的大量框线 |

本次密集框线的来源须区分 shape、offset/scale、`draw_limits`、选中状态及辅助绘制后再修复，不能只凭截图归咎于单一属性。不能用“曲线有值”“形状名存在”作为外观合格证据。

## 6. 三方验证、重载与画面验收

按[验证规范](Validation.md)分别记录，任何一项通过都不能替代其他项：

1. **示例 → 目标**：同角色比较接口、显示、行程、重置、骨骼及曲线；新角色比较功能语义及按比例适配的设计，不强求绝对坐标相同。
2. **Max → 目标**：比较完整变换、Morph、组合及限位。保留示例已知近似，不能用迁移一致性掩盖源偏差。
3. **目标正常帧**：核对 VM 所属资产和当前预览组件，确认时间推进；读取真实网格骨骼和最终动画曲线，恢复输入及最终输出。
4. **保存重载**：保存、关闭目标资产编辑器、重载目标包，复验结构、接口、显示依赖和数值；确认示例包未改动。无需关闭整个 UE。重编译或重开预览若重新标记包为 dirty，交付前再保存一次并确认目标包已干净。注意 `ControlRigRuntimeAsset` 在 5.8.4 上保存成功后会被立即重新标记 dirty（连续三次 `only_if_is_dirty` 保存都返回 `True`）；此时以磁盘写入时间、包摘要和重载后复验作为持久化证据，不把 dirty 标志本身当作失败，也不要反复保存刷状态。
5. **用户画面验收**：对照示例检查中性、中间/极限、左右和组合，检查拾取、拖动方向、面板遮挡、参考图及重置。未确认写“待用户验收”，用户指出明显差异则写“视觉验收未通过”。

先比较外观和操作，再扩大数值采样，避免完成数千样本后才发现控制设计已被替换。呈现有代表性的阶段结果，不使用 computer-use，也不因文档列了画面验收就要求用户批准每次可逆修改。

### 通过项与被跳过项分开记

验证前先确认每条基线属于哪个资产谱系。2026-11-10 流程验证中，12 个部位验证器里的“源动作段”全部通过，但 `regression_`/`old` 段因 `previous_controls.json` 属于已废弃的采样求解资产而误报失败（该文件 130 个 case 的 `bones` 为空，脚本回落到“全部骨保持中性”的期望）。因此：

- `previous_controls.json` 只在“升级同一求解、保留旧控行为”时才是必过项；从示例派生或空目标新建时，它不构成回归对象。
- 报告要分段给结论：结构、示例→目标、Max→目标、显示契约、保存重载、正常帧预览、用户画面。
- 被跳过的段要写原因和影响范围，不能把 `passed=false` 直接当成资产缺陷，也不能为了提高通过率伪造同谱系基线。

正常帧预览失败时按[预览停滞排障](../Troubleshooting/PreviewStall.md)处理；只重启一次并记录结果，仍不通过就明确写“未通过”，不能用数值通过代替画面证据。

Seven 的上眼皮近似、脸颊参考偏差和历史验证范围仍保留在[角色记录](../../Characters/Seven/README.md)。2026-11-10 从零采样重建虽通过数值及预览输出检查，用户已反馈其控制器外观与示例差异明显，因此不能作为新流程的合格外观基准。

## 7. 输出和交接

配置用独立 `Jobs/*.json`，报告放目标项目 `Saved/FaceMigration/Jobs/<job_id>/Current/Evidence/`，临时探测放 `Current/Temp/`。正式采纳的新角色参数按包约定归档，不改写 Seven 冻结证据，不为每次运行复制一套脚本或 README。

| 固定报告 | 内容 |
|---|---|
| `reference_inventory.json` | 示例路径、包摘要、控制/辅助显示契约和依赖 |
| `adaptation_report.json` | 示例、Max、目标的映射；每组保留/适配/修复及原因 |
| `layout_validation.json` | 对照视角、选择和调试状态；形状、颜色、轨道、参考图、行程及用户反馈 |
| `validation.json`、`reload_report.json` | 本轮三方功能、组合、限位、正常帧和重载；也可索引各阶段固定子报告 |
| `delivery_check.json` | 分列数值、预览、持久化、外观/操作和用户画面结论；已知近似与未测范围 |
| `flow_findings.md` | 本轮暴露的流程阻塞、误报和文档缺口；只写本任务证据，不改写历史结论 |

一目标一 job：新资产（例如 `NewControlRigRuntimeAsset1`）必须新建 `Jobs/*.json`，在 `asset_overrides` 把脚本内固定包路径映射到实际资产。映射只覆盖 `asset_path()` / `asset_disk_path()` 的调用点，脚本里的日志和外部命令不会自动跟随，换目标后要用 `probe_cr_migration.py` 复核 `target` 字段。

交接说明实际目标、已迁移功能、与示例的有意差异、操作方式和验证范围。仅数值通过时不能宣称“整体迁移验收通过”。
